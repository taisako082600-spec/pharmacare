# ファーマケア (PharmaCare)

**介護施設のスタッフと薬剤師をつなぐBtoBアプリケーション。**
服薬情報の共有、リアルタイム相談、訪問スケジュール管理、症状トリアージを統合しています。

調剤の現場に立つ薬剤師本人が、企画・設計・実装・ドキュメント整備までを単独で行っています。

---

## なぜ作ったか

介護施設では入居者の服薬情報が紙で管理され、処方変更のたびに電話やFAXで薬剤師に確認する運用が残っています。夜間や休日に入居者の体調が変化しても、施設スタッフは判断材料を持たず、薬剤師にもすぐ連絡が取れません。

この「情報が届かない構造」をシステムで解消することを目的としています。

---

## 設計上の判断

技術選定より、**医療領域固有の制約にどう対応したか**が本プロジェクトの中心です。

### AIに医学的判断をさせない

症状トリアージの判定は**決定論的なルールベースロジック**（[`llm-proxy/redflag.go`](llm-proxy/redflag.go)）で行い、LLMは「判定結果をわかりやすい日本語で説明する」役割のみを担います。LLMの確率的推論を診断・受診勧奨の判断には使いません。

さらに、**AI呼び出しが失敗しても判定結果は必ず返る**よう、クライアント側（[`lib/services/ai_drug_service.dart`](lib/services/ai_drug_service.dart)）にも同一ロジックをフォールバックとして実装しています。

### 安全側に倒しつつ、過剰警告を避ける

- 意識障害カテゴリーは**無条件で医療機関受診推奨**
- 危険信号が1つでも該当すれば、重症度スコアによらず受診推奨を優先
- ただし全てを「赤」にすると機能が使われなくなるため、**「危険信号」と「受診の目安になるサイン」を2段階に分離**

判定根拠は、医学書および厚生労働省公開資料をもとに構造化した内部文書として別途整備しています（**著作権への配慮から本リポジトリには含めていません**）。17症候・102件の危険信号を、症候別のアルゴリズムとして実装しています。

### 法的制約を前提に設計する

| 制約 | 対応 |
|---|---|
| 医師法 | 「診断」ではなく「目安の提示」に留め、最終判断は薬剤師・医師に委ねる導線を必須化 |
| 個人情報保護法 | 症状・健康情報は要配慮個人情報。Firestoreルールで施設・ロール単位にアクセスを制限し、ログイン・患者情報の参照/作成を監査ログに記録（改ざん・削除はルールで禁止） |
| 著作権 | 判定根拠の医学書はPDFを直接取り込まず、内容を確認の上で自分の言葉で再構成 |

### コスト上限を設計に組み込む

LLM APIの従量課金が想定外に膨らむリスクに対し、**施設単位と全体の二層でトークン予算の上限**を設定。並行アクセス時の安全性は200並行のテストで検証しています（[`llm-proxy/facility_budget_test.go`](llm-proxy/facility_budget_test.go)）。

## 技術構成

| 領域 | 採用技術 |
|---|---|
| クライアント | Flutter 3.44 / Dart 3.12（iOS・Android・Web） |
| バックエンド | Firebase（Cloud Firestore、Authentication） |
| APIプロキシ | Go（標準ライブラリのみ・外部モジュール非依存） |
| LLM連携 | Anthropic Claude API |
| コンテナ | Docker（マルチステージビルド） |

Firebase IDトークンのRS256署名検証は、外部SDKに依存せず標準ライブラリのみで実装しています（[`llm-proxy/auth.go`](llm-proxy/auth.go)）。テストは自己署名RSA証明書を用いて署名検証まで通しています。

## 主な機能

- **お薬手帳** - 薬剤師が患者の処方薬を一元管理
- **リアルタイムチャット** - 施設スタッフと薬剤師が情報交換
- **訪問スケジュール管理** - カレンダーで薬剤師の訪問日を共有
- **マルチ施設対応** - 薬剤師が複数施設に対応可能
- **招待コード連携** - 対面検証による安全な施設接続

## クイックスタート

### 1. 環境構築

```bash
# Flutter SDK をインストール
# https://flutter.dev/docs/get-started/install

# プロジェクトを取得
git clone https://github.com/taisako082600-spec/pharmacare.git
cd pharmacare

# 依存関係をインストール
flutter pub get
```

### 2. Firebase セットアップ

1. [Firebase コンソール](https://console.firebase.google.com) で `pharmacist-app-646df` プロジェクトを選択
2. Firestore と Authentication が有効化されていることを確認
3. `lib/main.dart` の `FirebaseOptions` を確認

### 3. アプリを起動

```bash
# Chrome で開発
flutter run -d chrome

# ホットリロード
# ターミナルで 'r' キー

# ホットリスタート
# ターミナルで 'R' キー
```

### 4. 初期セットアップ

詳細は [SETUP.md](./SETUP.md) を参照してください。

1. **管理者アカウント作成** - ロール「施設管理者」で登録
2. **テストデータ投入** - 管理画面「テストデータを投入」ボタン
3. **薬剤師と連携** - 招待コード発行 → 薬剤師がコード入力

## ロール体系

| ロール | 用途 | 権限 |
|---|---|---|
| **Superadmin** | システム管理者 | 全施設・ユーザー・統計管理 |
| **施設管理者** | 施設運営者 | 施設情報・薬剤師招待・スタッフ管理 |
| **薬剤師** | 医療従事者 | 処方薬管理・複数施設対応・予定作成 |
| **介護士** | スタッフ | 患者登録・チャット・情報閲覧 |
| **看護師** | スタッフ | 患者登録・チャット・情報閲覧 |

## 連携フロー

```
施設管理者
  └─ 「薬剤師との連携」 → 招待コード発行 → 薬剤師に対面で伝える

薬剤師
  └─ 「施設との連携」 → 「コードで連携」 → 6桁を入力 → 自動承認完了
```

## Firestore セキュリティモデル

- ユーザーは自分のドキュメントのみ読み書き可
- 患者情報は所属施設のスタッフ + 担当薬剤師のみアクセス可
- チャットルームは参加者のみ送受信可
- 招待コードは施設管理者が発行、使用済みフラグで管理

## ローカルテスト

### テストデータを投入

管理者ログイン → ダッシュボード → 「テストデータを投入」

以下が自動生成されます：
- 施設 1件（グループホームさくら）
- 薬剤師 1名（テスト薬剤師）
- 患者 3名（田中・佐藤・鈴木）
- 処方薬 各患者に1種
- 訪問予定 1件

### チャット機能確認

1. 管理者で管理画面 → 「この施設の画面を確認」
2. 介護士ロールでホーム → 「チャット」
3. 「全体連絡」ルーム → メッセージ送受信

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| ログイン失敗 | Firebase Auth未設定 | コンソールで認証を確認 |
| データが保存されない | Firestoreルールが拒否 | ルールをホットリロード後に確認 |
| チャット表示されない | roomID生成ロジック | Firestoreのrooms/{id}/messages確認 |
| 薬剤が削除できない | 権限がない | 薬剤師ロールで再度試す |
