# 第1部　デプロイ

## 事前確認

### まず最初にこれを実行する

```bash
node check_deploy_ready.js
```

認証・デプロイ先への疎通・ビルド成果物・Cloud Runの死活をまとめて確認します。
**Flutterのビルドは数十分かかるため、ビルド前に実行してください。**
（ビルドを待ってからデプロイで初めて認証エラーに気づく、という事故を防ぐためのものです）

### 認証について

デプロイの認証は `auth_helper.js` が次の順で解決します。

1. `.secrets/firebase-adminsdk.json`（あれば使う）
2. `gcloud auth login` のログイン情報（鍵が無いときはこちら。**通常はこれで十分**）

> ⚠️ **サービスアカウント鍵をダウンロードフォルダーに置かないでください。**
> Windowsのストレージセンサーが「14日間開かれていないファイルを自動削除」する設定に
> なっており、実際に鍵が消えてデプロイ不能になったことがあります（2026-08-16）。
> ごみ箱も経由しないため復元できません。置くなら `.secrets/` に置いてください。

## 本番デプロイ（Web）

> **`firebase deploy` は使わないこと。** このプロジェクトは `deploy.js` を経由します。
> firebase CLI を直接叩くと、次の3つが丸ごと飛びます。
>
> - **開発用の向き先の検出**（`assertNoDevEndpoints()`）— これが無かったため、
>   全端末が自分自身の localhost を叩く成果物が本番に出ていました（2026-08-27に発覚）
> - **キャッシュ回避**（`main.dart.js` をタイムスタンプ付きの名前にリネーム）
> - **古い世代の掃除**（放置すると `build/web` が数百MBに膨らみます）

### 手順

```bash
flutter build web --release
node deploy.js
```

`deploy.js` が成果物を検査し、開発用の向き先が残っていればデプロイ前に中止します。

### Firestore ルール

```bash
node test_rules.js        # 16ケース。攻撃と正規操作の両方を検証する
node deploy_firestore.js
```

ルールセットを作るだけでは有効になりません。`deploy_firestore.js` は
`cloud.firestore` リリースへの反映まで行います。

### LLMプロキシ（Cloud Run）

```bash
cd llm-proxy
go test ./...
gcloud run deploy pharmacore-llm-proxy --source . --region asia-northeast1
```

### 配信されたものを確認する

画面のエラー表示だけでは、壊れていることに気づけません。実物を見ます。

```bash
curl -s https://pharmacist-app-646df.web.app/flutter_bootstrap.js | grep -o 'main\.dart[^"]*\.js'
curl -s https://pharmacist-app-646df.web.app/<その名前> | grep -c 'localhost'   # 0 であること
curl -s https://pharmacore-llm-proxy-p6j6p3dn5q-an.a.run.app/ping
```

> Cloud Run では末尾が `z` のパスがエッジで処理され、コンテナに届きません。
> 死活監視には `/healthz` ではなく **`/ping`** を使います。

### ロールバック

Firebase Console → Hosting から前のバージョンに戻します。

## モバイル版について

**このアプリは Web 専用です。** `dart:js` / `dart:js_interop` を条件付きimportなしで
使っているため（QRスキャナ、記録の印刷、添付文書PDFの取り込み、二要素認証のエラー解析）、
Android・iOS 向けにはビルドできません。

以前ここにあった APK / App Store の手順は、**実行しても必ず失敗する**内容だったため
削除しました。モバイル対応が必要になった場合は、まず上記の web 専用 API を
条件付きimportに置き換えるところから始めることになります。

## CI/CD パイプライン（推奨）

GitHub Actions で自動デプロイ：

```yaml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - uses: actions/setup-java@v2
        with:
          java-version: '11'
      - run: flutter pub get
      - run: flutter test
      - run: flutter build web --release
      - uses: w9jds/firebase-action@master
        with:
          args: deploy --project pharmacist-app-646df
        env:
          FIREBASE_TOKEN: ${{ secrets.FIREBASE_TOKEN }}
```

## トラブル対応

### 患者が削除できない

**症状**: 「削除」ボタンを押しても削除されない

**対処**:
1. ネットワーク接続確認
2. Firestore ルールで権限確認
3. ブラウザキャッシュクリア → 再度試行
4. 管理者ダッシュボード → 削除

### チャットが表示されない

**症状**: メッセージが送信されたが相手に表示されない

**対処**:
1. Firestore → `rooms/{roomId}/messages` を確認
2. ブラウザの再読み込み
3. 通信状況確認（オフラインでないか）
4. Firestore ルール確認

### ユーザーがログインできない

**症状**: メール・パスワードが正しいのにログイン失敗

**対処**:
1. Firebase コンソール → 認証 → ユーザー で存在確認
2. ユーザーが無効化されていないか確認
3. email が正しく保存されているか Firestore で確認
4. 認証メール設定に誤りがないか確認

### 薬剤が重複して表示される

**症状**: お薬手帳に同じ薬が2個表示される

**対処**:
1. Firestore → `patients/{id}/medicines` で重複確認
2. 重複を削除（手動削除 or Cloud Function）
3. キャッシュ削除 → 再読み込み

## データ管理

### データバックアップ

Firestore は自動的に日次バックアップが行われます。

**確認方法**:
```
Firebase Console → Firestore Database → Backups
```

**復旧が必要な場合**:
1. Firebase サポートに連絡
2. 復旧ポイント（日時）を指定
3. 復旧実行（数時間かかる）

### データエクスポート

患者データを CSV で出力したい場合：

```bash
# Firebase CLI でエクスポート
firebase firestore:delete patients --recurse

# または、Admin SDK で処理
// 実装予定
```

### 監査ログの確認

誰が何をしたか確認：

1. 管理者ダッシュボード → 「監査ログ」（実装予定）
2. Firestore Console → `audit_logs` コレクション
3. `userId`, `action`, `timestamp` で検索

**主なアクション**:
- `CREATE` - データ作成
- `UPDATE` - データ更新
- `DELETE` - データ削除
- `LOGIN` - ログイン
- `LOGOUT` - ログアウト

## パフォーマンスチューニング

### クエリが遅い場合

**確認**:
```
Firebase Console → Firestore → Indexes
```

**最適化**:
1. 複合インデックスが必要なクエリはインデックス作成
2. `limit()` で結果制限
3. ページング実装

### 読み書き数が多い場合

**確認**:
```
Firebase Console → Usage
```

**削減方法**:
1. リアルタイムリスナーを必要な画面だけに
2. バッチ処理で複数の変更をまとめる
3. キャッシング実装

### ストレージ容量逼迫

**削減**:
1. 古いログを定期削除
2. 不要な画像・ドキュメント削除
3. アーカイブ用に別プロジェクト検討

## ユーザーサポート

### よくある質問

**Q: データはバックアップされていますか？**
A: はい。Firebase が自動的に日次でバックアップしています。

**Q: オフラインで使えますか？**
A: 現在は オンライン必須です。ローカルキャッシュ機能は今後実装予定です。

**Q: 削除したデータは復旧できますか？**
A: 完全削除の場合、Firebase サポートに連絡すれば復旧可能な場合があります（有料）。

**Q: チャット履歴はどのくらい保持されますか？**
A: 無制限に保持されます。必要に応じて手動で削除可能です。
