## ルート直下のスクリプト

| ファイル | 用途 |
|---|---|
| `deploy.js` | **Webのデプロイ。** 開発用の向き先が残っていたら中止する |
| `deploy_firestore.js` | Firestoreルールのデプロイ（リリースへの反映まで） |
| `test_rules.js` | 権限ルールのテスト16件 |
| `check_deploy_ready.js` | デプロイの前提条件をまとめて確認。**ビルド前に走らせる**（ビルドは数十分かかるため、認証エラーに後で気づくのが一番つらい） |
| `auth_helper.js` | 認証の共通処理。鍵が無ければ gcloud のログイン情報にフォールバック |
| `build_deck.js` | 紹介資料（pptx）の生成 |
| `extract_triage_data.js` | トリアージ資料のデータブロックを実装から生成 |
| `tools_render_check.js` | 上記資料の描画スクリプトを実際に走らせて検証。`JSON.parse` だけの確認では「JSは壊れているがJSONは正しい」を見逃したため |

## 整理の記録（2026-08-27）

重複と、実態と食い違う記述があったため整理しました。

| したこと | 理由 |
|---|---|
| `SETUP.md` を削除 | 「利用_使い方ガイド」と内容が重複。かつ**介護士は服薬記録が非対応**という古い記述と、ガイドラインが不要としている**パスワードの定期変更**を勧める記述があった |
| `DEPLOYMENT.md` を「運用_デプロイと障害対応」に統合 | どちらも運用する人向けで、参照する場面が同じ |
| `TESTING.md` を全面的に書き直し | 存在しない「テストモード」の手動手順書だった。実際のテスト4種に差し替え |
| デプロイ手順を書き直し | `firebase deploy` と書いてあったが、**それだと開発用の向き先を検出するガードを迂回する** |
| Android / iOS のビルド手順を削除 | `dart:js` を条件付きimportなしで使っているため、**実行しても必ず失敗する**内容だった |
| `.html` 版を削除 | `.md` と二重管理になり、必ず食い違う。公開版はArtifactにある |

**残っている注意点:** 「運用_導入から本番稼働まで」は初期に書かれたもので、
現在の実装（二要素認証の必須化、招待コードの8文字化など）を反映しきれていない
可能性があります。使う前に実装と突き合わせてください。
